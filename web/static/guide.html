02 / RESEARCH PIPELINE

질문이 증거로 바뀌는 경로

한 방향 파이프라인이지만, 실험 구간에서는 후보 코드가 트리처럼 갈라지고 평가 후 다시 합쳐집니다.

  1. 01
    INPUT연구 질문

    제목, 맥락, 키워드, 제약

  2. 02
    IDEATION가설 생성

    S2·arXiv·Kurate + 일반/반증 Codex 조사원

  3. 03
    PLAN실험 관리자

    데이터와 평가 기준을 구성

  4. 04
    AGENTIC TREE SEARCH코드 탐색

    초안 → 기준선 → 창의 실험 → 절제 실험

  5. 05
    EVIDENCE결과·플롯

    실행 지표와 시각 증거 집계

  6. 06
    WRITEUP인용·논문

    문헌 보강, 원고, PDF 생성

  7. 07
    REVIEW자동 동료평가

    결과물과 심사 기록 보존

STAGE 1Initial implementation

독립적인 초기 코드 후보를 만들고 실행 가능한 뿌리를 찾습니다.

STAGE 2Baseline tuning

측정 가능한 기준선을 안정화하고 명백한 오류를 줄입니다.

STAGE 3Creative experiments

새로운 메커니즘과 경쟁 가설을 넓게 탐색합니다.

STAGE 4Ablation studies

효과가 어디서 왔는지 구성 요소를 제거하며 검증합니다.

04 / OPERATIONS & RECOVERY

멈추면 어디서 다시 시작하나

긴 실행은 완전한 무중단이 아니라, 검증된 메인 단계 경계에서 안전하게 이어가는 방식입니다.

CHECKPOINT메인 단계 완료

저널, 설정, 탐색 상태를 영속 실험 폴더에 기록

INTERRUPTIONPod 재시작 / OOM / 프로세스 종료

작업 프로세스는 사라져도 PVC의 결과는 유지

RESTART다음 메인 단계로 복구

작업대의 ‘체크포인트 재시작’으로 같은 실험 폴더를 계속 사용

복구 경계

완료된 메인 단계만 확정 체크포인트입니다. 중간 서브스테이지 파일은 남아도 일부 계산은 다시 실행될 수 있습니다.

영속되는 위치

web_runs/에는 작업 메타데이터와 로그가, experiments/에는 코드·체크포인트·플롯·원고가 저장됩니다.

운영 제약

현재 배포는 GPU 한 조각과 24Gi 메모리 제한을 사용합니다. 동시에 하나의 전체 연구만 실행해 GPU와 결과 디렉터리를 보호합니다.

보안 경계

LLM이 생성한 코드를 실행하므로 신뢰된 네트워크와 격리된 런타임에서 운용해야 합니다. 이 작업대는 공개 인터넷용 인증 화면이 아닙니다.
